# Аудит проекта «Битва Классов»

## Вердикт

Сейчас это три несвязанных прототипа (бот, карта, SQL), а не система.
Единственное, что реально связывает их, — желание. Бот не знает про БД, фронт пишет в таблицы,
которых нет в схеме, а вся игровая «экономика» живёт в браузере игрока и может быть подделана за минуту.

## 🔴 Критично (блокирует MVP или безопасность)

| # | Где | Проблема | Решение в новой версии |
|---|-----|----------|------------------------|
| 1 | `bot/main.py` | **Токен бота и секретный код администратора лежат в коде.** Они попали в чат/репозиторий → считать скомпрометированными. | Перевыпустить токен у MAX, сменить ADMIN_CODE. Всё в `.env` (в `.gitignore`). |
| 2 | схема БД ↔ `script.js` | Фронт пишет в `map_hexes.institution_id` и `metadata`, а таких колонок нет → любой `insert` падает. `UNIQUE(q, r)` глобальный → второе учреждение невозможно. | Новая схема: `UNIQUE(institution_id, q, r)`, явные колонки вместо JSON `metadata`. |
| 3 | `script.js` | **Захват целиком на клиенте**: `Math.random()` для цены (вызывается дважды: в окне и при подтверждении → цены разные), введённые очки нигде не списываются, баланса нет. Любой может вызвать `supabase.from('map_hexes').update(...)` из консоли. | Сервер считает цену детерминированно, списывает ОД в транзакции с блокировками. Клиент шлёт только `hex_id`. |
| 4 | RLS | Только `SELECT` с `USING (true)`. Либо запись не работает вообще, либо её «лечат» открытой политикой на запись — тогда читерство тривиально. | RLS включён без политик: anon-ключ ничего не может. Единственный писатель — backend. |
| 5 | всё | **Нет авторизации.** Фронт не использует `initData` MAX, бот даёт выбрать роль «Администратор»/«Куратор» кому угодно. | Backend проверяет подпись `initData` (HMAC от токена бота). Куратор/админ — только по коду. |
| 6 | `getDistanceToNearestOwnedHex` | Если своих гексов нет, возвращается `-1`, а `multiplier = distance > 0 ? … : 1` → **захват бесплатно-дёшево без штрафа**. | Расстояние считается формулой осевых координат, случай «нет гексов» обработан явно. |
| 7 | `loadHexesFromDB` | После перезагрузки `hexRadius = 0` → позиции всех гексов схлопываются в центр. Формула центра также отличается от генератора (нет смещения на centroid). | Сервер хранит `lat/lng` каждого гекса и `hex_radius_m` учреждения. |
| 8 | `HexGridLayer` | Canvas с `pointer-events:auto` и `z-index:500` перекрывает карту → **карту нельзя двигать и зумить мышью/тачем**. | Canvas пассивный, клики/hover слушаются на самой карте Leaflet. |

## 🟠 Серьёзно

- **Бот: глобальный флаг `waiting_for_admin_id`** — один на всех. Два пользователя одновременно → код получит не тот. Весь «ID-хак» (`отправьте точку`) не нужен: в callback-событии user_id есть.
- **Роли и состояния в памяти процесса** (`user_roles`, `user_states`) — после рестарта все разлогинены. Профиль в боте захардкожен («Иван, 10-А, 150 очков»).
- **Гонка генерации**: `hexesExist` → `generate` → `insert` на клиенте. Два первых посетителя создадут дубли карты. Генерация перенесена на сервер под `pg_advisory_xact_lock`.
- **Дублирование кода**: `Script_to_data_base_and site.js` — устаревший прототип (координаты Москвы, другая формула гексов, `const supabase = supabase.createClient(...)` → ReferenceError, URL проекта `https://supabase.co`). Удалить.
- **Нет начисления ОД.** Ключевая механика игры («классы зарабатывают ОД») не реализована: ни ledger, ни доход от гексов, ни выдача куратором.
- **XSS**: `toast.innerHTML` и `legend.innerHTML` вставляют имена из БД без экранирования.
- **Бот управляет «количеством гексов учреждения»** — это не игровая сущность. Заменено на выдачу ОД классу.

## 🟡 Мелочи

- `index.html` подключает supabase-js дважды; в `script.js` заглушки ключей.
- Перемешивание `sort(() => Math.random() - 0.5)` смещённое; генерация недетерминирована (нельзя воспроизвести карту).
- BFS на `queue.shift()` — O(n²).
- `hex.color + '2e'` ломается, если цвет не `#rrggbb`.
- Пустые `readme.txt`, `.gitignore`; нет Docker, тестов, миграций, healthcheck.

## Целевая архитектура

```
 MAX Messenger ──► Bot (maxapi)  ─┐   X-Service-Key + X-Acting-User-Id
 MAX WebApp ──► nginx ──/api──►   ├─► Backend (FastAPI) ──► PostgreSQL
   (Leaflet+Canvas, initData)    ─┘      │  ▲ единственный писатель
                                          └──┘ фоновый job: ежедневный доход ОД
```

Принципы: клиент и бот — «тонкие»; правила игры только в `backend/app/rules.py`;
деньги (ОД) — только через `ap_ledger` (аудируемый журнал) + атомарный баланс класса.

## Игровые правила MVP (зафиксированы в коде)

- Класс получает ОД: (а) от куратора/админа за успехи (`/grant`), (б) ежедневный доход = сумма `daily_points` его гексов.
- Цена захвата = `ceil((20 + 40·value) · 1.5^d · (1.5, если гекс занят врагом))`, где `d` — расстояние до ближайшего своего гекса.
- Домашние гексы захватывать нельзя. Нейтральные — дешевле, чем вражеские.
- Ценность гекса `value` — близость к центру; домашние (у края) дают 1 ОД/день.

## Что осталось за рамками MVP

Реальный контур здания вместо круга 100 м, интеграция с электронным журналом (авто-ОД за оценки),
защита гекса (гарнизон), Realtime-обновление карты (сейчас polling 15 с), push-уведомления из бота.

# Битва Классов

Игра для школьников в мессенджере MAX. Классы получают очки действия (ОД) за успехи в учёбе и тратят их на захват секторов на карте своей школы. Карта состоит из шестиугольников, наложенных на реальную местность. Побеждает класс, который удерживает больше территории.

## Как это устроено

Три части, одна база:

- `backend/` — API на FastAPI. Здесь живут все правила игры: цена захвата, списание ОД, ежедневный доход. Это единственный компонент, который пишет в базу.
- `bot/` — бот для MAX на библиотеке `maxapi`. Регистрация, профиль, рейтинг, начисление ОД кураторами. Своей логики не имеет, только вызывает API.
- `frontend/` — карта на Leaflet с гексами на Canvas. Статика за nginx, запросы к `/api` проксируются в backend.
- `db/init.sql` — схема PostgreSQL и демо-данные (две школы, восемь классов).

Раньше часть расчётов выполнялась в браузере и фронтенд ходил в Supabase напрямую. Это позволяло любому игроку выдать себе очки или чужие сектора, поэтому правила перенесены на сервер. Что именно было не так, описано в [AUDIT.md](AUDIT.md).

## Запуск

Нужны Docker и Docker Compose.

```bash
cp .env.example .env
docker compose up --build
```

Сайт откроется на http://localhost:8080. Для первого запуска ничего в `.env` менять не нужно.

### Посмотреть карту без MAX

Вход в игру идёт через подпись MAX, поэтому без мессенджера карту можно открыть только в режиме отладки. В `.env` поставьте `DEV_MODE=1`, перезапустите и зарегистрируйте тестового игрока из 10-А (в демо-данных у класса 300 ОД):

```bash
curl -X POST http://localhost:8080/api/register \
  -H "X-Dev-User-Id: 123" -H "Content-Type: application/json" \
  -d '{"role":"schoolboy","class_id":1,"display_name":"Test"}'
```

В PowerShell:

```powershell
Invoke-RestMethod -Method Post http://localhost:8080/api/register `
  -Headers @{"X-Dev-User-Id"="123"} -ContentType "application/json" `
  -Body '{"role":"schoolboy","class_id":1,"display_name":"Test"}'
```

Затем откройте http://localhost:8080/?dev_user=123, нажмите на сектор и подтвердите захват. Карта школы создаётся при первом открытии.

### Запуск бота

Боту нужен токен из кабинета MAX. Заполните в `.env` `BOT_TOKEN`, `SERVICE_KEY` (любая длинная случайная строка), при необходимости `ADMIN_CODE` и `CURATOR_CODE`, и запустите с профилем `bot`:

```bash
docker compose --profile bot up --build
```

Чтобы кнопка «Открыть карту» работала из MAX, сайту нужен публичный HTTPS-адрес. Его указывают в `WEBAPP_URL`.

## Готовые образы

Каждая часть собирается в свой образ: `classwar-db`, `classwar-backend`, `classwar-frontend`, `classwar-bot`. Схема базы запечена в образ `classwar-db`, поэтому для запуска достаточно образов и `docker-compose.yml`, исходники не нужны.

```bash
# собрать и выложить на Docker Hub (REGISTRY — ваш логин)
REGISTRY=логин TAG=1.0 docker compose --profile bot build
REGISTRY=логин TAG=1.0 docker compose --profile bot push

# запустить из готовых образов
REGISTRY=логин TAG=1.0 docker compose up
```

## Правила игры

Все формулы лежат в `backend/app/rules.py`.

- Куратор или администратор начисляет классу ОД за успехи в учёбе.
- Каждый сектор раз в сутки приносит владельцу несколько ОД. Чем ближе к центру карты, тем сектор ценнее. Секторы у края дают по 1 ОД.
- Цена захвата: `ceil((20 + 40·ценность) · 1,5^d)`, где `d` — расстояние в гексах до ближайшего сектора своего класса. Если сектор занят другим классом, цена выше в 1,5 раза.
- У каждого класса есть домашний сектор. Его захватить нельзя.

Каждое списание и начисление записывается в таблицу `ap_ledger`, поэтому любой спорный баланс можно разобрать.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | проверка работы |
| GET | `/api/institutions/{id}/map` | карта, классы и рейтинг |
| GET | `/api/institutions/{id}/leaderboard` | рейтинг классов |
| GET | `/api/me` | профиль текущего пользователя |
| POST | `/api/register` | выбор роли и класса |
| GET | `/api/hexes/{id}/quote` | цена захвата сектора |
| POST | `/api/hexes/{id}/capture` | захват сектора |
| POST | `/api/classes/{id}/grant` | начисление ОД (куратор, администратор) |
| POST | `/api/institutions/{id}/reset` | пересоздать карту (администратор) |

Авторизация: подпись `initData` из MAX для веб-приложения, общий ключ `SERVICE_KEY` для бота.

## Тесты

```bash
pip install pytest
pytest backend/tests
```

Тесты покрывают расчёт расстояний, цену захвата и генерацию карты.

## Известные ограничения

- Проверка подписи `initData` написана по схеме, которую используют мини-приложения мессенджеров. Её нужно сверить с документацией MAX Bridge на реальном устройстве.
- Бот написан под `maxapi`, но с живым сервером MAX проверен не был. Разбор данных из событий вынесен в три функции в начале `bot/main.py`, при другой версии библиотеки править нужно только их.
- Контур здания пока заменён кругом радиусом 100 м вокруг координат школы.
- Карта обновляется опросом раз в 15 секунд, без push-уведомлений.
- Очки за учёбу вносит куратор вручную. Интеграции с электронным журналом нет.
